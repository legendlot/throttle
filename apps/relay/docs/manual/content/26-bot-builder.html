A bot is a scripted conversation on the website chat widget (and optionally WhatsApp): menus, order status, agent handoff. It uses the same canvas as journeys, on a Journeys | Bots toggle. Bots have no trigger, no exit rules, no versions screen and no funnel — just a definition, a status, and a test.

Where
Journeys screen, Bots toggle.
Read or act?
Action screen. A published, active bot answers customers on its own.
Who
Author builds and saves drafts, Manager also publishes, pauses/resumes and sets WhatsApp rollout.
Channels
Web widget, WhatsApp (support number), or Shared flow (used by other bots).

The bot list

Each row is a bot: name, status (draft / active / paused), channel, live version, and its last 7 days — chats, handled, handoffs to agents, and conversions (a session whose customer placed an order within 24 hours of the chat starting). Open loads it onto the canvas; New bot starts a blank web-widget draft.

Building the flow

Add a step

Buttons above the canvas add: Message, Menu, Ask for input, Order status, Hand to agent, End chat, Shared flow. Drag from a node’s right-edge dot to another node to wire an outcome.

Chat start

The fixed anchor node (the same node journeys use for their trigger, relabelled). It fires when the customer opens the widget (on WhatsApp: their first message); wire its one outcome to your first step.

Duplicate step

Select a node, then Duplicate step in the panel below. You get a copy with the same settings, offset slightly. The copy is not wired to anything — connect it yourself, then Save draft. The copy becomes the selected node, so the panel opens on the new one, not the original. A copied Menu keeps its option labels but gets new option ids, so a customer tapping an old button on the original menu is never sent down the copy’s branch.

Delete step

Delete step in the same panel, or select the node and press Backspace or Delete. Removes the connections into and out of it too.

Expand

The Expand button (top-right of the canvas) fills the screen, docking the Step / Settings / Test panel beside it. Esc exits.

Only one connection is kept per outcome: dragging a new wire from a dot that is already wired replaces the old one, it does not add a second.

Step types

Message

Sends text, one outcome (next).

Menu

Shown as Buttons or a List. One outcome per option, plus Not understood (the fallback branch, taken after two misses in a row — wire it, usually to Hand to agent). Matches either a tapped button or a typed reply that matches an option’s label or number; anything else re-shows the menu until the miss cap.

Ask for input

Collects Phone or email (identity) or an Order number. An invalid answer re-asks once; a second invalid answer takes Not understood (the fallback branch — publish refuses it unwired). Typing a keyword configured in Settings jumps straight to that keyword’s step instead of counting as a miss.

Order status

Needs a Phone or email ask and an Order number ask earlier in the flow. Looks the order up and verifies it: the order’s own phone/email must match what the customer already gave. Order found and Not found / no match are the two outcomes — a mismatch and a genuinely missing order both take Not found / no match, on purpose, so the bot never confirms which order numbers exist. After 5 failed lookups the bot says the step’s configured text and hands off.

Hand to agent

Terminal. Ends the bot’s part of the conversation and lands it in the Pitstop inbox as a thread; the bot never speaks again in that conversation. The order-lookup cap hands off the same way — a customer the bot cannot help reaches a person, never silence.

End chat

Terminal. Optional goodbye text, then the session ends.

Shared flow

Jumps into another bot built with channel Shared flow. Only a shared flow that is published and active can be picked. When the shared flow ends, the customer continues on this step’s next. The chat runs the shared flow’s live version at the moment it enters — so publishing a shared flow changes it for chats already under way, and pausing one hands those chats to an agent when they reach this step.

⚠ Watch out — WhatsApp limits

Buttons: max 3 options, 20 characters each. List: max 10 rows, 24-character titles. The canvas only warns about these (it does not know the bot’s channel yet); Publish enforces them for real, per channel — including inside a Shared flow, since it can be called from a WhatsApp bot too.

Settings

Channel (fixed after the first publish, since sessions and the inbox key on it), keywords (an answer the bot did not accept jumps straight to a step; on WhatsApp the opening message counts too — the web widget opens without one), and for a WhatsApp bot, rollout: Pilot (only the numbers listed) or Public (every customer on the number). Rollout needs the activate permission, and going Public is Afshaan’s call.

Test panel

Runs the current draft (unsaved edits included) against a simulated customer. It is side-effect-free: nothing is written, no order is looked up and nobody is handed off — those steps show as → would look up… and → would hand off to an agent here. Entering a Shared-flow step in the test always follows that flow’s draft, not its published version — the live bot always runs the published one, so a draft-only difference in a shared flow will not show up here.

Note

The Test panel only appears when nothing else is selected. Click empty canvas to get back to it after configuring a step.

Saving and publishing

Every outcome on every step must be wired before you can publish — an unwired menu button or an unwired fallback is a customer reaching a dead end. Save draft is available to anyone who can build; Publish (freezes a version; every new conversation gets it at once) needs the activate permission.

⚠ Save draft, THEN Publish

Publish ships the last saved draft, not what is on the canvas. Edits you have not saved — even ones you just ran through the Test panel — are not published and are not checked.

Pause and resume

Pause keeps the published version but stops new conversations. On the web widget, a new visitor sees Chat is unavailable right now — please email support@legendoftoys.com; a chat already open carries on to its end. On WhatsApp the bot goes quiet at once, even mid-chat — a customer it was talking to can sit out of the Pitstop Awaiting list while they keep writing, so check the inbox for them after a pause. Pausing a Shared flow hands off any chat that reaches it. Resume — or Publish, which also sets the bot active — brings it back.

⛔ Important

Save draft never touches what customers see. Publish does, at once, for every conversation that starts after it — a conversation already in progress finishes on the version it started with, except inside a Shared flow, which always runs that flow’s current version. Run the change through the Test panel, save, then publish.
