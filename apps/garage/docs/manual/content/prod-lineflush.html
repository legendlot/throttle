A line flush is how leftover, unused or damaged materials come back to the store after a run. Production raises the flush (lists what they are sending back); the store verifies it on the Flush Verify screen. This screen is the production side plus the shared register.

What it’s for
Returning leftover materials after a run.
Read or act?
Action: raise a flush.
Who
Production (raise) Store (verify) Admin
Status
Pending → Verified.

Raising a flush

  1. + New Flush. Set the date, type (against a Production Run or Standalone), line and shift. For a run, pick it from the list of recent in-house runs.
  2. Add the parts being returned. Use Load From Run to pull the run’s pick list, or add parts by hand. For each part, split the quantity by return type: Unused, Damaged, QC Rejected, Partial Assembly or Wrong Issue.
  3. Submit Flush. It goes to the store as Pending Verification; the store counts what actually arrived and decides where each part goes.

The list shows each flush with its status: Pending Verification (yellow), Verified (green), Disputed (red). A red banner warns when flushes are waiting on the store. The Quarantine Register tab is a read-only list of parts the store set aside with their bin locations.

ⓘ Production proposes, the store counts

Raising a flush records what production believes they are returning. The store’s verified count is the figure that actually moves stock (see Flush Verify), and any mismatch is logged. Outsourced runs do not appear in the flush run picker.
