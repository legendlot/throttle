Production Runs is where the store views and manages builds: each run’s consolidated pick list, confirming what the floor received, and the outsourced send / receive / finish steps. Runs are no longer created here, they are requested in Redline (New Run / Request); this screen is where you track and act on them.

What it’s for
Viewing and managing runs (not creating them).
Read or act?
Manage: receipts, outsourced steps.
Who
Production Admin
Lifecycle
Draft → Submitted → Issued → Completed.
ⓘ Runs are requested in Redline now

To start a run (fresh, outsourced, repair or repack), use Redline’s New Run / Request screen. The old “+ New Run” / “+ Repair Run” buttons here have been removed so there is one place to request a run. This Garage screen keeps everything after the request: the pick list, receipt confirmation, reject / complete, and the outsourced send / receive / finish steps.

Managing a run

Click a run to open its detail: the consolidated pick list (grouped by category and part type, with shortfalls flagged), the work orders inside it, and the buttons to cancel, reject, confirm receipt, mark complete, and run the outsourced send / receive / finish steps. Repair runs open their own detail (units scanned in at the repair station, not a parts pick).

⚠ Confirming receipt with a shortfall

When you confirm receipt and what the floor got is short of what was issued, the system automatically raises a Short Supply work order so the store re-issues the gap. (Run requests, including the fresh run date and colour, are set in Redline’s New Run / Request.)

Outsourced runs (two-phase)

An outsourced run sends raw materials to a vendor who builds and returns the units. New outsourced runs split into a build half (done outside) and a finish half (done in-house), so only the parts the vendor needs go out and the packaging stays in until the units return. The run detail (View) carries the buttons for each step:

BUILD    Store issues the build pick (Car / Remote / Fastener only)
         -> Send to Vendor (run goes In Progress)

RECEIVE  Vendor returns units (instalments OK)
         -> Receive built units (count) into the pool        [run detail]

FINISH   -> Issue Finish Parts (packaging / accessories / battery / sticker)
         -> sticker each unit at Ext Inwarding (scanner) -> QC -> PKG Out

The pick list for a new outsourced run shows the build parts only, so the store issues just those; the finish parts are issued later with Issue Finish Parts, once the units are back. Use Receive built units on the run detail to count returns into the pool as they arrive. Outsourced runs created before this change keep their original one-step receive (assign a line, scan each unit at Ext Inwarding).

ⓘ Requests now start in Redline

Production raises every run, including outsourced and repair, from Redline’s New Run / Request screen. This Garage screen still shows and manages the runs, and is where the outsourced send-out, receive and finish steps live.
