Ad Hoc Requests is where production asks for parts outside a planned run: a one-off need that the store then issues from the Issue Queue. Open it to raise a request or to check and cancel open ones.

What it’s for
One-off parts requests to the store.
Read or act?
Action: create / cancel.
Who
Production Admin
Then
Store issues from Issue Queue.

Raising a request

  1. + New Ad Hoc Request. Choose BOM-Based (pick a product and category, and it adds all that category’s parts) or Manual (type each part code; the name fills from the parts master).
  2. Set quantities, line, shift and date. Edit the quantity on each part line.
  3. Link a repair run (optional). If these parts are for a repair run, pick it from the Repair Run dropdown (open runs are listed). The request is then tagged to that run, so we can see which parts repairs actually consume.
  4. Create Request. A WO number is generated and the request appears in the store’s Issue Queue.

The Open Ad Hoc Requests table lists each request with its status: Open (yellow), Pending Rework (blue), Cancelled / Rejected (red), Complete (green). Open or pending-rework requests can be cancelled.

ⓘ Repair parts build a useful record

Linking a request to a repair run (and choosing the product in BOM mode) attributes those parts to the run. Over time this shows which parts repairs really need, so we can stock extra and eventually plan repair runs properly. The linked parts appear on the repair run’s detail in Redline.

⚠ Switching modes clears your lines

Toggling between BOM-Based and Manual resets the parts you have added, so choose the mode first. In Manual mode the part name only fills if the code matches the parts master; an unrecognised code is accepted as typed but has no name.
