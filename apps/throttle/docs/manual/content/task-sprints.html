Sprints is where leads plan the week’s work: pull tasks from the backlog into the active sprint, give them due dates, watch progress, and close the sprint when it ends. A sprint runs Thursday to Wednesday.

What it’s for
Planning and running the sprint.
Read or act?
Action: build and close sprints.
Who
Lead Admin
Cycle
Thursday to Wednesday (7 days).

Running a sprint

  1. Create the sprint (when none is active). The start date must be a Thursday; only one sprint runs at a time.
  2. Fill it from the backlog. Drag tasks from the Backlog panel into the Current Sprint panel; a prompt lets you set a due date within the sprint week. Drag a task back out to remove it.
  3. Watch progress. A header bar shows percent done and a day countdown; a 7-day timeline lays out tasks by due date.
  4. Close the sprint when the week is over. Any unfinished tasks become spillovers and a new sprint is created automatically.
ⓘ “Overdue: close sprint”

When the Wednesday end date passes, the header prompts you to close the sprint. Closing rolls the incomplete tasks forward as spillovers (marked on their cards) into the next sprint, so nothing is lost. Use the / search to find a task across the sprint and backlog.
