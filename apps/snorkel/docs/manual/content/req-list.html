The PO Requests screen lists every request that has been filed and where each one stands. It is the shared inbox between the people who ask for things and the procurement team who buys them.

What it’s for
Tracking requests from filed to bought.
Read or act?
Read, with actions on each request.
Who
Requester Procurement Admin
Tabs
All, pending, approved, rejected, cancelled.

Reading the list

Tabs across the top split requests by status, each showing a live count. Every row shows the request number, title, category, urgency, estimated cost, who filed it, the date, and the status. When a request has been turned into a purchase order, its number appears under the approved badge so you can see what it became.

StatusWhat it means
pendingFiled, waiting for procurement to act.
approvedTurned into a purchase order and that PO was accepted. The linked PO number is shown.
rejectedProcurement declined it, with a reason.
cancelledThe person who filed it withdrew it.

Opening a request

Click any row to open it. The detail screen shows everything that was filed and what can be done now, which depends on your role and the request’s status:

  • Make PO from request Procurement — starts a new purchase order with the request shown alongside, so you can copy the details across.
  • Reject Procurement — declines the request; a reason is required and is shown back to the requester.
  • Cancel request — only the person who filed it can withdraw their own pending request.
ⓘ Accepting the PO closes the loop

A request is marked approved not when the PO is created, but when procurement accepts that PO. Until then the request stays pending and shows the draft PO it is linked to. This means a half-built draft will not falsely tell the requester their thing is on the way.
