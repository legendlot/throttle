Some parts are bought in a bulk unit (a roll of shrink wrap, a packet, a box) but issued and costed by the piece. Purchase Units is where a buyer tells Snorkel what that bulk unit is and how many pieces it holds, so the part’s per-piece cost can derive itself from the PO instead of being typed in by hand.

What it’s for
Bulk-unit → per-piece cost conversions.
Read or act?
Manage with permission.
Who
Procurement (Raise PO)
Feeds
Every part’s stored per-piece cost.

What’s on the list

The list holds every active part that has ever been bought on an India PO in a unit other than pcs, so a per-piece cost cannot yet derive for it. For each part you see the part code, name and category, every unit and price it has actually been bought at (with the PO number), its stored weight in grams if it has one, and its current cost.

Setting the conversion

Type what the part is bought as (Roll, Packet, Box, whatever the vendor calls it) and how many pieces that one unit holds, then Save. The row shows a live preview of the per-piece cost as you type, worked out from the part’s latest PO line. Once saved, that per-piece cost is what the rest of Snorkel reads as the part’s unit cost, and it keeps re-deriving itself from PO history from then on: you are not typing a cost, you are telling the system how to work it out.

Worked example

Shrink Wrap 14×18 is bought as a Roll of 2,200 pieces. A PO priced at ₹5,040 per roll becomes ₹2.29 per piece, and that is the figure everywhere else in Snorkel treats as this part’s cost.

⛔ kg is not set here

A part bought by weight (screws, for example) already converts through its stored weight per piece, so it never needs an entry on this screen and the Bought as / Pieces per unit fields stay blank for it. If a kg-derived cost looks wrong, the fix is a re-weigh of the part, not a row here.

Set both fields, or clear both

A unit with no pieces count (or a count with no unit) does nothing, Snorkel asks you to set both or clear both before it will save.

Re-derive all costs

Use Re-derive all costs to re-run the derivation for every part against its full PO history in one pass, useful after a bulk edit or if something looks stale. Snorkel reports how many costs were applied, rejected or left unchanged. It never blanks a cost that already exists, and it refuses to write a value that looks like a bulk price wearing a per-piece label (a shrink-wrap roll priced at ₹390 landing as ₹390 per piece, say), those show up as rejected rather than silently overwriting a correct cost.

It also runs itself

Every time a PO is accepted, the same derivation runs automatically for the parts on that PO, so most costs stay current without a visit to this screen at all. Re-derive all costs is for catching up the rest, or checking nothing has drifted.
