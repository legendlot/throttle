New Run / Request is the single place production asks for any kind of run. One screen, four tabs: Fresh, Outsourced, Repair and Repack. Whatever you request lands in the store’s Issue Queue as something to issue, so there is one consistent “what does the store owe right now” list across every run type.

What it’s for
Requesting any run: Fresh, Outsourced, Repair, Repack.
Read or act?
Action.
Who
Operator Supervisor Admin with run-request access.
Where it goes
The store’s Issue Queue (Garage).

Production owns every run request. The store never issues stock on its own; it only fills a request that lands in its queue. Each tab below explains how the materials move, step by step, and which system handles each step.

Fresh

A normal in-house build. Pick the product, line, shift and the variant quantities (E-Comm and Retail). The run is created and submitted to the store; the store issues the full pick list and the floor builds it on the line. Nothing about fresh runs changed.

Outsourced

Raw materials go to a vendor who builds the units and returns them. This is now a two-phase run, so only the parts the vendor needs go out, and the packaging stays in until the units come back.

BUILD  (outside)
  1. Request Outsourced Run (pick vendor)        -> store Issue Queue
  2. Store issues the BUILD parts                -> Car / Remote / Fastener only
  3. Hand to vendor, then Send to Vendor (Garage)-> run goes In Progress

VENDOR builds. Units come back (in instalments is fine).

RECEIVE  (store)
  4. Receive built units (count) into the pool   -> Garage run detail

FINISH  (in-house, when a line is free)
  5. Issue Finish Parts                          -> packaging / accessories / battery / sticker
  6. Sticker each unit at Ext Inwarding          -> then QC -> Packaging -> PKG Out
ⓘ Only car, remote and fastener go to the vendor

The packaging, accessories, battery and sticker are issued later, in-house, when the built units return. You receive the returns as a simple count (instalments are fine), then issue the finish parts and sticker each unit at Ext Inwarding.

Repair

An open-ended recovery run for the broken / returned pile. You can start it with no target: just open the run and the floor pulls units in as they go. Add target product lines only if you already know what you are recovering.

  1. Request Repair Run (no target needed)
  2. Floor: at Repair Start, sticker each repairable unit and scan it in
              (scrap goes straight to the scrap pile, no scan)
  3. Repair it; when a part is short, raise an Ad-Hoc Request (Garage)
              linked to this repair run -> store Issue Queue
  4. QC -> Packaging -> PKG Out  (QC fail -> Workshop -> QC, as normal)
ⓘ Ad-hoc parts are tracked per run

Parts requested for a repair run are linked to that run (and product) in Garage’s Ad Hoc Request screen. Over time this builds a picture of which parts repairs really need, so we can buy extra and eventually structure the run.

Repack

Swap a unit’s channel packaging when you need stock in one channel but it is packed for the other. Enter the product, the from and to channel, and the quantity.

  1. Request Repack Run (product, from -> to channel, qty)
       -> raises TWO requests:
          (a) store: issue the TO-channel packaging (box + tray)  -> Issue Queue
          (b) dispatch: release the units                         -> "to release" list
  2. Dispatch: at Repack Release, scan each box to hand it over   (sign-off)
  3. Repack In: scan the old box label                            (only released units)
  4. Repack Out: new flipped label (channel set from the request) -> PKG Out -> dispatch
⚠ Units must be released by dispatch first

This is the only place material moves backwards in the factory, so it is tightly controlled. A unit sitting with dispatch (Dispatch In or Allocated) cannot be repacked until a dispatch operator releases it at the new Repack Release station. Repack In hard-rejects anything that was not released. Units still on the production side (just out of PKG Out) do not need a release.
