## What this is

66 SQL files that load the entire historic Omnipresent sheet into the
`ignition` schema:

| Set | Files | Rows |
|---|---|---|
| Staging schema | `00-schema.sql` | 3 tables created |
| Influencers | `01..32-influencers.sql` | 1,251 (Master Data + B-List) |
| Engagements | `50..64-engagements.sql` | 434 (Video Tracking + UGC) |
| Discount codes | `80..96-codes.sql` | 1,000 |
| Drain | `99-drain.sql` | mints engagement_no, inserts into real tables, drops staging |

All idempotent on `legacy_sheet_ref` / `influencer_code` / `code` UNIQUE
constraints — safe to rerun.

## Rerunning

Safe. The drain block checks `legacy_sheet_ref` existence before inserting
and the staging tables use `ON CONFLICT (…) DO NOTHING`. Drop staging tables
manually if you want to start fresh:

```sql
drop table if exists ignition._stage_influencers;
drop table if exists ignition._stage_engagements;
drop table if exists ignition._stage_codes;
```

Then rerun the importer to regenerate the .sql files and re-apply.
